# T5 — workbook tools: measurement and native evidence (`list_sheets`, `add_sheet`)

**Дата:** 2026-10-06. **Sprint 4, серия T5** (операции с книгой и листами).
Окружение нативных прогонов: **R7-Office Editors 2026.3.1**, Windows, `doctype=spreadsheet`, одноразовая книга.

**Статусы:**

- **Windows runtime = VERIFIED** для `list_sheets` и `add_sheet`: исполнялись **поставочные** тела, извлечённые
  из собранного артефакта, через вендорский канал `Asc.plugin.callCommand`, с независимой проверкой чтением.
- **Astra runtime для T5 = NOT VERIFIED**: харнесс на целевом стенде поднят и работает (см. evidence T4.0 §13),
  но серия T5 на нём ещё не прогонялась. Метод тот же — поставочный артефакт ставится на стенд и исполняется его
  же телом; это предмет exit-gate.

## 1. Измеренная поверхность книги (T5.0)

| вопрос | измеренный ответ |
| --- | --- |
| коллекция | `Api.GetSheets()` — **массив** объектов-листов (`length` = счётчик, порядок = порядок индексов), у каждого `GetName()`/`GetIndex()`/`GetVisible()` |
| разрешение листа | `Api.GetSheet(name)` и `Api.GetSheet(index)` возвращают один и тот же лист; неизвестное имя → `null` |
| **идентичность объектов** | **непригодна для «активный»**: `GetSheet('…') === GetActiveSheet()` даёт `false` (разные обёртки одного листа) → активный определяется по **имени/индексу** |
| добавление | `Api.AddSheet(name?)` возвращает **`undefined`**, лист добавляется **последним** и **становится активным**; без имени — **локализованное** `Лист1` |
| адресация другого листа | только через объект листа: `sheet.GetRange('A1')`; **квалифицированный** `GetRange('Sheet!A1')` **бросает** исключение |
| переименование | `SetName()` подтверждается тремя читателями; движок **переписывает межлистовые ссылки** (`=SrcSheet!A1` → `=RenamedSheet!A1`) |
| видимость | `GetVisible()`/`Visible`; `asc_getHiddenWorksheets()` |
| удаление | `Delete()` измерен, но **вне scope T5** |

## 2. `list_sheets` (T5.1, коммит `f948e3d`)

Первый инструмент уровня книги: без аргументов, отвечает `{count, activeIndex, activeName, sheets:[{name,index,active,visible}]}`.
Активный лист помечается **по индексу**; список **не обрезается** — книга выше `LIMITS.sheetListMax` (64) это
известный отказ. Вложенную форму валидирует декодер, обработчик перепроверяет скаляры.

**Нативное доказательство** (поставочное тело + собственные читатели редактора как третье свидетельство):

```
readers baseline : count=1, 0:Sprint1, activeIndex=0, collectionElementIsActiveObject=false
listing baseline : [1,0,'Sprint1','Sprint1',0,1,1]
после Api.AddSheet('T5Proof')      : [2,1,'T5Proof','Sprint1',0,0,1,'T5Proof',1,1,1]
после переименования               : [2,1,'T5Renamed',…,'T5Renamed',1,1,1]
после СКРЫТИЯ (SetVisible(false))  : [2,0,'Sprint1','Sprint1',0,1,1,'T5Renamed',1,0,0]   ← visible=0
после показа и удаления            : [1,0,'Sprint1','Sprint1',0,1,1]  (книга как была)
maxSheets: 0                       : ['CAPABILITY_UNAVAILABLE']
```

## 3. `add_sheet` (T5.2)

Единственная мутация книги: ровно один `Api.AddSheet(name?)`, возврат которого **не** читается как успех/провал.
Вердикт — postcondition, доказываемый **декодером**: счётчик вырос ровно на один; новый лист **последний**; его
имя — прочитанное из редактора (при заданном имени должно совпасть); новый лист **активен** по паре
`(index, name)`; прежние листы сохранили порядок **поэлементно**; прежний активный лист на месте; имя
действительно новое. Результат: `{index, name, active: true, previousActive:{index, name}}`.

**Два отказа до мутации** (книга не меняется): имя уже существует; добавление превысило бы `LIMITS.sheetListMax`.
**После мутации известного класса отказа нет**: любое неоднозначное состояние → `UNCERTAIN` с **удержанным
слотом**, без повтора, и **лист не удаляется**. Прежний активный лист **сообщается, не восстанавливается**.

**Нативное доказательство** (оба поставочных тела + читатели):

```
readers baseline : count=1, 0:Sprint1, activeIndex=0
listing baseline : [1,0,'Sprint1','Sprint1',0,1,1]
add name=T5Added : ["POST_INSERT",1,2,1,"T5Added",1,"T5Added",0,"Sprint1","Sprint1","Sprint1","T5Added"]
listing after    : [2,1,'T5Added','Sprint1',0,0,1,'T5Added',1,1,1]
readers after    : count=2, 0:Sprint1, 1:T5Added, activeIndex=1
add ТО ЖЕ имя    : ["PRE_INSERT","TOOL_ERROR"]     (список не изменился — отказ до мутации)
add maxSheets=2  : ["PRE_INSERT","TOOL_ERROR"]     (граница до мутации)
add БЕЗ имени    : ["POST_INSERT",2,3,2,"Лист1",2,"Лист1",1,"T5Added",…]   ← локализованное имя, прочитано
cleanup → listing restored: [1,0,'Sprint1','Sprint1',0,1,1]; readers count=1, activeIndex=0
```

## 4. Адресация листа в `read_range` (T5.3a, коммит `db130a0`)

Существующее чтение получило **необязательный селектор листа** в двух закрытых формах: `sheet` (имя) и
`sheetIndex` (0-based индекс) — потому что измеренный `Api.GetSheet(name | index)` принимает и то и другое, а
диалект схемы не знает объединения типов. Указание обоих — отказ как неоднозначность. **Без селектора поведение
прежнее** (активный лист), и селектор уходит в редактор явным `null`, а не угаданным именем. Разрешение — только
через `Api.GetSheet(...)`, и **и значения, и формульный проход** читаются с **объекта этого листа**, поэтому
активный лист не переключается. Несуществующий лист — **известный отказ**: новый, более узкий однослотовый
`['TOOL_ERROR']` рядом с прежним `['CAPABILITY_UNAVAILABLE']`. Форма результата не менялась: `sheetName`/
`sheetIndex` описывают **прочитанный** лист.

**Измерено нативно попутно (числовая строка как имя):** `Api.GetSheet('1')` при отсутствии листа с таким именем
отвечает **`null`** — то есть **коэрции числовой строки в индекс нет**; после добавления листа, буквально
названного `1`, тот же вызов отвечает этот лист (имя побеждает). Поэтому `sheet: '1'` — это имя, а не индекс.

**Нативное доказательство** (поставочное тело чтения; книга с двумя листами с РАЗНЫМИ данными в `A1:B1`;
после каждого чтения снимался `Api.GetActiveSheet().GetName()`):

```
подготовка   : active=Sprint1
без селектора: ["Sprint1",0,2,"A1:B1","A1:B1",1,2,1,2,1,"sprint-a1","sprint-b1","",""]   active=Sprint1
sheetName Второй : ["Второй",1,2,"A1:B1",…,"second-a1","second-b1","",""]                active=Sprint1
sheetName Sprint1: ["Sprint1",0,2,…,"sprint-a1","sprint-b1","",""]                       active=Sprint1
sheetIndex 1     : ["Второй",1,2,…,"second-a1","second-b1","",""]                        active=Sprint1
sheetName '1' при отсутствии такого имени : ["TOOL_ERROR"]                              active=Sprint1
sheetName НетТакого / sheetIndex 7         : ["TOOL_ERROR"]                              active=Sprint1
уборка       : deleted Второй, deleted 1; active=Sprint1; count=1
```

Независимые ревью: **approve with nits, без блокеров** во всех трёх задачах. Крупные находки T5.3a — реальные
пробелы покрытия: `sheetIndex: 0` нигде не проверялся (три правдоподобные реализации `|| null` молча читали
активный лист), а формульный проход, читающий активный лист, был неотличим, потому что тесты селектора не
проверяли `formulas` — теперь это пинено двумя листами, у которых **вычисленное значение совпадает, а источник
разный**. Восемь нитов закрыты там же: граница имени, мёртвая опция стенда, `readSheet`, который молча
проглатывал селектор, несогласованность класса отказа, документированное переиспользование `sheetListMax`,
самоописывающее описание, закреплённый класс для не-объекта и числовая строка (снята нативной пробой).

## 6. Что НЕ проверено

* **Astra runtime для T5** — не прогонялся (см. статусы выше);
* сквозной путь «модель → реестр → инструмент → мост → тело» — предмет exit-gate P&L;
* `rename_sheet`, адресация листа в `write_range` (T5.3b) и `format_cells` (T5.3c), а также `delete_sheet` —
  следующие шаги/вне scope;
* `read_sheet` селектор **намеренно не** выставляет (его поведение не изменилось).
