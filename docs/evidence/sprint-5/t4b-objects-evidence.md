# Sprint 5, T4b — native evidence: `add_table` + `add_image` (2026-10-07)

**ЦЕЛЬ.** Подтвердить на живых редакторах, что поставочное тело создаёт таблицу и картинку, **доказывает**
результат по самой документной структуре, отказывает до мутации на некорректный запрос и что обе мутации
откатываются штатным маршрутом редактора.

**ЧТО ИСПОЛНЯЛОСЬ.** Тело `slideobject` извлекается из поставочного `dist/plugin/panel.js` (генератор
`t4b-native-proof.mjs`, 9 484 символа) и исполняется в фрейме плагина. Независимый читатель перечисляет
коллекции слайда и разбирает `ToJSON()` последних рисунков — то есть читает **документ**, а не ответ тела.
Измеренная база — `docs/evidence/sprint-5/t4-slide-mutation-measurement.md`.

**СТЕНДЫ.** Astra SE 1.7.9.41 + Р7 **2026.1.2-1942** (целевой) и **Windows R7-Office Editors 2026.3.1**;
поставочный `panel.js` — `ea91f4d4…`; одноразовая колода, ничего не сохранялось.

## 1. Успешный путь: порядок аргументов доказан, а не угадан

| запрос | Astra | Windows | независимое чтение документа |
| --- | --- | --- | --- |
| таблица 3 колонки × 2 строки | `[4, 0, 3, …]` | `[4, 0, 3, 2, 4, 6]` | созданный рисунок: `gridCols=3`, `tcPr=6` → 6 ячеек = 3×2 |
| таблица 2 колонки × 4 строки | `[4, 0, 2, …]` | `[4, 0, 2, 4, 5, 8]` | `gridCols=2`, `tcPr=8` = 2×4 |
| картинка 1×1 PNG, 720000×360000 EMU | `[5, 0, 1, …]` | `[5, 0, 1, 720000, 360000, 118]` | `hasRaster=true`, `GetWidth()=720000`, `GetHeight()=360000` |

Второй запрос с **другими** колонками и строками — это и есть проверка порядка: транспонированный вызов дал бы
`gridCols`, равный числу строк, и доказательство не сошлось бы (рига содержит отдельный тест на такую подмену).

Некорректные запросы — `columns 0`, `columns 9` (за потолком), `rows 21`, дробное число колонок, mime не из
списка, пустой источник, `width 0`, `width` за потолком — **все** дали `[0, 'TOOL_ERROR']` **до** диспатча, на
обоих стендах.

## 2. Дефект, найденный приёмкой, и его исправление

Первая версия тела читала `tblGrid` в **корне** разобранного JSON, тогда как измеренная структура кладёт его под
`graphic` (`{"graphic":{"tblGrid":[…],"tblPr":{…},"content":[…]}}`). Данные были верны — обе таблицы реально
создавались (`gridCols=3/tcPr=6` и `2/8` в независимом чтении), — но доказательство не сходилось, и обе ноги
честно отвечали `APPLY_UNCERTAIN`. Исправлено: доказательство читает `graphic.tblGrid` с защитой (JSON без
`graphic` или с не-объектом по-прежнему даёт неопределённость, а не исключение). Рига приведена к измеренной
форме JSON и дополнена тестами на транспонированную таблицу и на отсутствующий `graphic`.

## 3. Undo — критерий приёмки каждой мутации

Маршрут: `g_asc_plugins.api.WordControl.m_oLogicDocument.Document_Undo()` из фрейма редактора.

| мутация | результат |
| --- | --- |
| одна таблица (3×2) | **откатывается**: `drawings` 4 → 3, история исчерпана (`canUndo` → `false` после #3) |
| картинка | **откатывается**: после серии undo `images` 1 → 0 и `drawings` 6 → 5 |
| смешанная последовательность (таблица, таблица, картинка) за 10 вызовов | откатилась картинка; таблицы остались, история ещё не исчерпана — то есть дело в **глубине**, а не в невозможности |

Глубина отката — свойство группировки движка (тот же класс, что измерен в T3/T4a): точечные маршруты требуют
нескольких вызовов, `CreateNewHistoryPoint()` картину не меняет. Критерий «мутация откатывается» выполнен для
каждого класса по отдельности.

## 4. Чего этот прогон НЕ показывает

* **Содержимое ячеек, ширины колонок, стиль таблицы и геометрия** не читаются — инструмент их и не обещает.
* **Пиксели и позиция картинки** не проверялись: доказан источник (`rasterImageId`) и размер, а не отрисовка.
* **Порядок объектов** и глубокая неизменность уже существующих объектов доказуемы только на уровне счётчиков
  измеренных коллекций (тождество обёрток на этой поверхности нестабильно).
* Сохранение и повторное открытие (Save/reopen) — предмет exit gate.
* Расхождений Astra ↔ Windows в этом прогоне **не обнаружено**: ответы совпали по форме и по числам.
