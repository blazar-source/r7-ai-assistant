# Sprint 5, T5 — native evidence: `duplicate_slide` + `move_slide` (2026-10-07)

**ЦЕЛЬ.** Подтвердить на живых редакторах, что поставочное тело дублирует и переносит слайд, **доказывает**
результат по отпечаткам слайдов, отказывает до мутации на индекс вне диапазона и что **обе** мутации откатываются
штатным маршрутом редактора.

**ЧТО ИСПОЛНЯЛОСЬ.** Тело `sliderestructure` извлекается из поставочного `dist/plugin/panel.js` (генератор
`t5-native-proof.mjs`, 8 303 символа) и исполняется в фрейме плагина. Независимый читатель печатает отпечатки
слайдов: `layoutLen`, `layoutHead`, число объектов, тексты объектов и длину `slide.ToJSON()`.

**СТЕНДЫ.** Astra SE 1.7.9.41 + Р7 **2026.1.2-1942** (целевой) и **Windows R7-Office Editors 2026.3.1**;
поставочный `panel.js` — `4aa44d38…`; одноразовая колода, ничего не сохранялось.

## 1. Успешный путь (Astra и Windows совпали по семантике)

| запрос | Astra | Windows |
| --- | --- | --- |
| `duplicate_slide` слайда 3 (середина, несёт текст) | `[6, 7, 6, 3, 11200, 2]` | `[6, 6, 5, 3, 11185, 2]` |
| `duplicate_slide` слайда 0 | `[6, 8, 7, 0, …]` | `[6, 7, 6, 0, …]` |
| `duplicate_slide` индекса 99 и −1 | `[0, 'TOOL_ERROR']` | идентично |
| `move_slide` 5 → 0 | `[7, 8, 5, 0, …]` | `[7, 7, 5, 0, 11185, 2]` |
| `move_slide` на тот же индекс (идемпотентно) | `[7, 8, 0, 0, …]` | `[7, 7, 0, 0, 11185, 2]` |
| `move_slide` вне диапазона (99) и −1 | `[0, 'TOOL_ERROR']` | идентично |

Форма ответов: дублирование — `[6, slidesCount, copyIndex, duplicatedFrom, layoutLen, shapes]`, перенос —
`[7, slidesCount, fromIndex, toIndex, layoutLen, shapes]`. **Копия действительно оказывается в конце** (индекс =
прежнее число слайдов), как и измерено: при 5 слайдах копия — индекс 5/6, при 6 — 6/7.

Независимое чтение после операций (Astra): после двух дублирований и одного переноса — 8 слайдов, и на индексе 0
стоит слайд с `texts=["WHOLE_OBJECT_TEXT",""]` (перенесённая копия слайда 3), а прочие отпечатки совпадают с
прежними по значениям.

Расхождение **только в длине сериализованного layout** (Astra 11 200 / Windows 11 185) — это различие сборок, а не
поведения; доказательства сравнивают значения внутри своего стенда.

## 2. Undo — критерий приёмки каждой мутации

Маршрут: `g_asc_plugins.api.WorkControl.m_oLogicDocument.Document_Undo()` из фрейма редактора (до 10 вызовов),
после каждой мутации отдельно.

| мутация | до | после мутации | после 10 undo |
| --- | --- | --- | --- |
| `duplicate_slide` слайда 3 | 5 слайдов | 6 слайдов (копия на индексе 5) | **5 слайдов** — копия снята |
| `move_slide` 4 → 0 | слайд 0 = пустой (`jsonLen 34762`), слайд 4 = «SPRINT1…» (`29383`) | слайд 0 = «SPRINT1…» (`29383`), слайд 4 = «WHOLE_OBJECT_TEXT» | **порядок восстановлен точно**: слайд 0 = пустой (`34762`), слайд 4 = «SPRINT1…» (`29383`) |

То есть обе мутации **откатываются**, и для переноса доказательством служит именно возврат **порядка** отпечатков —
как и требует §15.5. Глубина: история после серии доходит до `asc_getCanUndo() = false`.

## 3. Чего этот прогон НЕ показывает

* **Визуальный порядок** слайдов на экране не проверялся; доказаны структура и отпечатки.
* **Заметки, скрытые слайды, анимации** в колоде отсутствуют — их влияние не измерено.
* Побайтовая идентичность дубликата **не** заявляется: измерено, что `jsonLength` копии отличается от источника.
* Роль placeholder'а (`type 3`/`13`) измерена в `t5-slide-restructure-measurement.md`, но как **новый аргумент**
  инструментов не вводилась.
* Сохранение/повторное открытие — предмет exit gate.
