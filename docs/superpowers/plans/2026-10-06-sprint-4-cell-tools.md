## 1. Принципы (зафиксированы владельцем)

- Инструменты **пользовательского уровня и достаточно крупные**: одна операция = законченный осмысленный результат (диапазон ячеек, оформленный блок, лист), а не элемент разметки.
- **Не делаем микротулы** вида `set_cell_bold`, `set_cell_fill`, `set_cell_border`. Оформление — **один bounded range-инструмент с закрытой схемой** (`format_range`), а не семейство мелких сеттеров.
- Каждый инструмент: **TDD → native verification на одноразовой книге → независимый review → атомарный коммит**.
- Каждый mutating-инструмент обязан назвать **способ подтверждения** (readback). Если подтвердить нельзя — исход `TOOL_UNCERTAIN`, лок держится, **повтора мутации нет** (правило Sprint 3, действует и здесь).
- **Перед реализацией используется уже измеренная API surface** (§2). Если конкретное свойство не подтверждено — делается **точечный native probe**, а не широкий research.
- Если публичный primitive отсутствует: зафиксировать точный runtime FAIL (API, сценарий, наблюдение) → targeted поиск готового решения в официальной документации / issues / плагинах → предложить рабочую альтернативу. Точный FAIL зафиксирован честно, «глухой» блокировки всего Sprint 4 нет.
- Agent Runtime (`src/agent/*`) **не меняется**: расширение идёт дескрипторами `src/tools/cell.js` и плечами `src/plugin/bridge.js`.
- Никаких push/merge/публикации: только локальные коммиты и чистое рабочее дерево.

**Измеренные правила, которые T4/T5 обязаны учитывать (не переоткрывать):**

- `range.SetFormula` **не существует**; `GetRowsCount`/`GetColumnsCount`/`GetMaxRow`/`GetMaxColumn`/`GetCell` — `undefined`.
- Десятичная дробь, записанная как **JS number**, сохраняется как ТЕКСТ; локальная строка (`'12,5'`) сохраняется как **число**.
- Парсер формул **locale-aware**: разделитель аргументов `;`, десятичный `,`; точка (`.`) в исходнике формулы **молча очищает ячейку**.
- Целое JS-число хранится числом; **строка с ведущим нулём (`'007'`) приводится движком к числу** (`7`) и не может быть записана этим маршрутом — исход fail-safe UNCERTAIN.
- Формула, вычисляющаяся в ошибку, отдаёт значение **только после пересчёта** (`=1/0`: сразу `""`, позже `#DIV/0!`), поэтому формула подтверждается **по формуле**, а не по значению.
- Возврат нативного валидатора сохраняет **плоские массивы примитивов** и **срезает plain object** — форма провода выбирается с учётом этого.

## 5. T2 — Bounded Cell reads — DONE

- `read_sheet` — чтение used range листа.
- `read_range` — чтение адреса, закрытого формой `A1` или `A1:C10`.
- **Bounded truncation по ЦЕЛЫМ СТРОКАМ**: ответ всегда несёт полную форму диапазона, реально покрытый адрес и явный флаг `truncated`, поэтому усечённое чтение нельзя спутать с полным. Диапазон, чья единственная строка шире лимита, отказывает закрыто, а не публикует частичную строку.
- **Контракт values + formulas:** значение и формула — два слота ответа; форма провода — один плоский массив примитивов (plain object срезается нативным валидатором), декодер закрывает все прочие формы.
- **Коммит:** `0f1cef791fe8c904119cf8e6a31b119d390b5325` — «feat(tools): add the first Cell tools, read_sheet and read_range» (он же содержит строку «Sprint 4 begins»).

### KNOWN DEFECT T2 — слот `formulas` публикует ВЫЧИСЛЕННЫЕ ЗНАЧЕНИЯ вместо исходных формул

Измерено на поставочном теле чтения:

```
чтение K1    (K1 = 'A')       -> [...,"A","A"]            formulasMatch 1, formulas ["A"]
чтение K1:K2 (K2 = '=1+1')    -> [...,"A","2","A","2"]    formulasMatch 1, formulas ["A","2"]
```

То есть для блока слот `formulas` содержит **значение** `2` там, где ожидался **исходник** `=1+1`, а чтение 1×1 у однобуквенной ячейки публикует **сам символ** как её «формулу». Причина — измеренное правило: **multi-cell `GetFormula()` возвращает значения**, а тест формы (`claimed.length === totalRows`, длина строки `=== columnCount`) такую матрицу значений пропускает (скалярная строка тоже имеет числовой `.length`).

**Последствия, которые фиксируются явно:**

- **T2 нельзя считать окончательно исправным по чтению формул**, пока этот дефект не закрыт отдельной corrective-задачей (§10.A).
- Вызывающему, которому нужен **исходник** формулы, сейчас приходится читать адресно — по одной ячейке через single-cell `GetFormula()`; API-контракт инструмента этого не обещает.
- Дефект **не исправляется внутри T4/T5** и не смешивается с ними: это отдельный атомарный коммит (§10.A), выполняемый **ДО** начала T4.

## 6. T3 — `write_range` — DONE

- **значения** (числа/текст) и **текст** как есть;
- **целые** значения — числовым маршрутом (JS-число, ровно до 15 цифр), **дробные** (`'0.15'`, `'12.5'`) — в ЛОКАЛЬНУЮ числовую форму, которую сообщает сам движок (`Api.GetLocale()`; измерено 1049 = ru-RU, разделитель — запятая), и доказываются ЧИСЛОМ, а не написанием: движок печатает сохранённое число канонически, поэтому `'1.0'` возвращается как `'1'`. **Готовая локальная строка (`'12,5'`) уходит как локальная строка — измерено, что это настоящее число. Набор comma-локалей перечислен в теле, локаль вне набора получает точку и доказывается написанием (числовая претензия не заявляется).
- **формулы** — ячейка, начинающаяся с `=`, пишется как формула;
- **bounded verification** — один ограниченный readback ровно по адресованному блоку, **один флаг на ячейку**; формульная ячейка подтверждается **владением формулой** (адресное single-cell `GetFormula()`), остальные — совпадением значения после единственной нормализации;
- **no retry on uncertain mutation** — всё, что не доказано после записи (`POST_INSERT`), переходит в `UNCERTAIN`: лок удерживается, повтор запрещён; известным отказом (`PRE_INSERT`) считается только то, что отвечено **до первого `SetValue`**;
- **native + bundle-body proof** — доказательство снято и с тела, извлечённого из `src/plugin/bridge.js`, и с тела, извлечённого из **собранного бандла** (15/15 на блоке `A1:C5`, плюс 1×1-набор и негативные контроли);
- **коммит:** `388638917233005d59f4435be8e96205f742c6a6`.

**Осознанно не обслуживаемый класс (измерено):** код из одних цифр с **ведущим нулём** (`'007'`) движок приводит к числу, readback это опровергает, исход — fail-safe UNCERTAIN. Тихо перенумерованный счёт недопустим, поэтому отказ сохранён и задокументирован.

## 7. T4 — Cell formatting

**Цель:** агент должен уметь не просто записать расчёт, а **оформить полноценную финансовую таблицу**.

**Целевой high-level инструмент:** **один** bounded range-инструмент с закрытой схемой (никаких `set_cell_bold` и подобных).

**Имя реализации — `format_cells`, а не `format_range`** (плановое имя). Причина измеренная: `format_range` уже
владеет Word-нога, а bulk-профиль реестра фильтрует инструменты **по имени**, поэтому дубль отдал бы bulk-прогону
по таблице ровно один инструмент форматирования; переименование Cell-ноги сохраняет классификацию, не трогая
общий реестр (Agent Runtime не меняется).

**Статус T4.0 — DONE.** Поверхность форматирования измерена, схема и числовой контракт зафиксированы, dev cap
откалиброван; полная матрица «свойство → сеттер → readback → Windows → Astra surface → supported»,
закрытый контракт number-format, границы значений, семантика `fill`/очистки и калибровка производительности
1..400 ячеек — в [T4.0 evidence](<../../evidence/sprint-4/t4.0-format-range-evidence.md>).

**Статус T4.2 — DONE.** Реализация закрыта коммитом `7b0480b` (docs-правка — `6108cd9`), нативное
доказательство снято **из поставочного артефакта**: тело `cellformat` извлекается из собранного `panel.js` и
исполняется на живом редакторе штатным каналом `Asc.plugin.callCommand`.

* Границы: внутренний слой рантайма плагина (реестр/дескриптор/мост) бандл наружу не экспонирует, поэтому сквозной

**Минимальная область (целевые свойства; каждое подтверждается до реализации):**

- числовой формат: **number / percentage / currency** — в той мере, в какой это поддерживает публичный API;
- **bold / italic**;
- **font family / size / color** — где поддерживается;
- **fill / background**;
- **горизонтальное и вертикальное выравнивание**;
- **границы**;
- **ширина колонки / высота строки / autofit** — если подтверждённый публичный API это поддерживает.

**Порядок работ T4:**

1. **T4.0 — точечный probe (bounded, без фич-кода).** По уже измеренной поверхности (§2) определить: какие **сеттеры** форматирования существуют и — обязательно — какие **читаемые getters** существуют для каждой группы свойств. Мутация обязана иметь способ подтверждения, поэтому свойство без читаемого getter **не может** получить доказательство; такой случай либо получает подтверждённый альтернативный bounded-способ, либо честно выводится из области с зафиксированным FAIL.
2. **T4.1 — реализация `format_cells` (план: `format_range`).** Закрытая схема: адрес диапазона (та же форма, что у `read_range`) + объект оформления, все поля которого закрыты и валидируются; никаких «произвольных» свойств. Пишутся только **подтверждённые** группы свойств; неподтверждённые отсутствуют в схеме, а не игнорируются молча.
3. **T4.2 — native proof + независимый review.** Доказательство — readback оформления по адресованному диапазону (значения и формулы при этом **не меняются** — это проверяется отдельно). Оформление должно быть видно и в нативном чтении, и в конвертированном представлении, если конвертация доступна.
4. **T4.3 — коммит.** Атомарный, со своим тестовым набором и нативной записью.

**Ограничения T4:** Agent Runtime не меняется; существующие `read_sheet`/`read_range`/`write_range` не переписываются «попутно»; новые группы свойств добавляются только после измерения.

## 8. T5 — Workbook / worksheet operations

**Цель:** дать агенту возможность строить **много-листовые** модели, включая запрос вида «создай P&L и отдельный лист допущений».

**Целевая функциональность (каталог — только из подтверждённых публичных primitives):**

- `list_sheets` / чтение структуры workbook (какие листы есть, какой активный);
- `add_sheet`;
- **выбор/адресация нужного листа**;
- `rename_sheet` — **только если безопасно подтверждается**;
- **адресация листа в существующих инструментах**: `read_range`, `write_range`, `format_cells` должны работать с **явно указанным** листом, а не только с текущим активным.

**Статус T5.0 — DONE.** Поверхность книги измерена на живом редакторе; из неё следуют четыре правила,
которые держит вся серия: активный лист определяется по ИМЕНИ/ИНДЕКСУ (идентичность объектов измеренно непригодна:
`GetSheets()[i]` и `GetActiveSheet()` — разные обёртки одного листа); `AddSheet(name?)` возвращает `undefined`,
новый лист — последний в списке и СТАНОВИТСЯ активным, а имя читается обратно (без имени получается
локализованное `Лист1`); другой лист адресуется только объектом из `Api.GetSheet(name|index)` (квалифицированный
адрес `GetRange('Sheet!A1')` измеренно БРОСАЕТ исключение); переименование безопасно — движок переписывает
межлистовые ссылки (`=SrcSheet!A1` → `=RenamedSheet!A1`).

**Статус T5.1 — DONE** (коммит `f948e3d`). `list_sheets` — первый инструмент уровня книги: без аргументов,
отвечает списком с именем/индексом/активностью/скрытостью и отказывает (не обрезает) книге выше
`LIMITS.sheetListMax`. Нативно доказан на поставочном теле: базовый список совпал с собственными читателями
редактора, а после add/rename/hide/show/delete список отражал каждое изменение (`visible=0` для скрытого листа)
и вернулся к базовому.

**Статус T5.2 — DONE** (коммит `4f3d1b9`). `add_sheet` — первая мутация книги: ровно один
`Api.AddSheet(name?)`, возврат которого не трактуется как успех/провал; вердикт — postcondition, доказываемый
декодером (счётчик +1, новый лист последний, имя прочитано, активен по паре `(index, name)`, прежние листы
сохранили порядок поэлементно). Имя необязательно и никогда не предсказывается; существующее имя и превышение
`sheetListMax` — известные отказы **до** мутации; после мутации известного класса нет (UNCERTAIN, слот удержан,
лист не удаляется); прежний активный лист **сообщается, не восстанавливается**. Нативно доказан на поставочных
телах: именованное добавление, повтор того же имени (отказ до мутации), граница, добавление **без** имени
(локализованное имя прочитано) — с независимым подтверждением чтением и возвратом книги в исходное состояние.

Полная матрица замеров книги, нативные трассы и результаты гейта T5.1/T5.2 — в
[T5 evidence](<../../evidence/sprint-4/t5-workbook-tools-evidence.md>).

**Статус T5.3a — DONE** (коммит `db130a0`). Существующее чтение получило необязательный селектор
листа в двух закрытых формах (`sheet` — имя, `sheetIndex` — индекс; оба сразу — отказ), без селектора поведение
прежнее. Разрешение — только через измеренный `Api.GetSheet(...)`, и **и значения, и формульный проход** читаются
с объекта выбранного листа, поэтому активный лист не переключается (проверено нативно после каждого чтения).
Несуществующий лист — известный отказ: новый узкий однослотовый `['TOOL_ERROR']` рядом с прежним
`['CAPABILITY_UNAVAILABLE']`. Форма результата не менялась — `sheetName`/`sheetIndex` описывают прочитанный
лист. Замерено попутно: числовая строка **не** коэрцится в индекс (`Api.GetSheet('1')` при отсутствии такого
имени отвечает `null`), поэтому `sheet: '1'` — это имя.

**Статус T5.3b — DONE** (коммит `d25a6b7`). Тот же селектор на мутации: закрыт до диспатча на обоих
слоях, неизвестный лист — известный отказ **до** первой записи, разрешённый лист обслуживает запись и **все**
доказательства, `POST_INSERT` — непосредственно перед первым `SetValue`, активации нет вообще. **Измерено перед
контрактом:** запись в неактивный лист **не** двигает активный лист (узкая проба) — закреплено тестом. По итогам
ревью добавлена **сверка разрешённого листа с запросом до записи** (readback читает тот же объект, который писал, и
потому не может заметить, что объект — не тот лист) и **обновлено описание инструмента**: это единственное
модельное поле, и без него селектор был необнаружим моделью. Форма ответа намеренно не менялась (это per-cell
доказательство T3), поэтому ответ не называет лист — ограничение зафиксировано явно; нативная трасса и замер
active sheet записаны в evidence (§5).

**Статус T5.3c — DONE** (коммит `b133bc6`). Селектор перенесён на вторую мутацию: закрыт на обоих
слоях до диспатча, неизвестный лист — известный отказ без единого форматирующего вызова, разрешённый лист
**сверяется с запросом** до первого сеттера, и **все** сеттеры (включая блочные width/height) вместе со **всеми**
проверочными чтениями работают на выбранном листе. Измерено перед контрактом: форматирование неактивного листа не
двигает активный лист. Описание инструмента называет оба аргумента, и тест читает **содержание** описания — урок
reject'а по T5.3b применён сразу. T4-контракт не тронут: `decodeCellFormat` байт-в-байт. Ревью T5.3c дало
**reject по доказательствам** (не по коду): требование «все сеттеры» было доказано для 3 из 9 — теперь proof-на-каждый-сеттер,
плюс проверка `properties` через реальный мост и непустые интеграционные пины.

**Статус T5.4 — DONE, СЕРИЯ T5 ЗАКРЫТА** (коммит `0f9fb34`). Переименование листа: источник
выбирается как в остальных ногах, `newName` обязателен и закрыт; занятое имя (включая собственное текущее) и
отсутствующий источник — известные отказы **до** мутации; после `SetName` вердикт — postcondition по **независимым
читателям** (число листов, порядок поэлементно, сохранённый индекс, новое имя разрешается, **старое больше не
разрешается**); активный лист **записывается**, не переключается и не восстанавливается; в теле **ровно один**
`SetName` и **никакого отката**. Измерено, а не предположено: переименование активного листа оставляет его
активным под новым именем, а имя длиннее 31 символа движок **молча отклоняет** → post-mutation `UNCERTAIN` со
удержанным слотом, не ложный успех. Переписывание межлистовых ссылок (`= Данные!A1` → `= Итог!A1`) принято
нативно **один раз**. Ревью T5.4 снова дало **reject по доказательствам** без дефекта кода: порядок фаз не
проверялся ничем и его нарушение **fail-OPEN**, слот `POST_INSERT` не имел случая, числа были с устаревшей
ревизии. Всё закрыто, включая **переписанный раннер мутантов** (он мог молча бить по чужой ноге и выдавать это за
выжившего — теперь отказывает неоднозначным якорям, печатает место попадания и работает в копии).

**ДВА ИЗВЕСТНЫХ ОТКРЫТЫХ ПУНКТА Cell-пути (найдены на Astra, не правились).**
1. Панель по умолчанию включает «передавать выделение», а чтение контекста требует Word-редактора: на книге это
   даёт `CAPABILITY_UNAVAILABLE` **до** обращения к модели — при настройках по умолчанию прогон на таблице
   умирает, не дойдя до модели (тумблер приходится снимать вручную).
2. Остаточный предел доказательства записи: строка чтения не несёт тип, поэтому ТЕКСТОВАЯ ячейка, чья запись
   совпадает с канонической записью числа (`0.15`), неотличима от ЧИСЛА; числовая претензия заявляется только для
   маршрутов, выбранных самим телом (запятая — по измеренной локали), а вне набора значение доказывается написанием.

**Cell-тулкит больше не растёт.** Дальше — Sprint 4 exit gate: реальный сценарий P&L → калибровка Qwen → нативная
верификация на Astra → независимое финальное ревью.

**Порядок работ T5:**

1. **T5.0 — точечный probe.** Подтвердить реальные (не presence-only) примитивы: перечисление листов, количество листов, добавление листа, чтение/установка имени, признак активного листа, и **как адресовать диапазон на конкретном листе**.
2. **T5.1 — `list_sheets`** (read).
3. **T5.2 — `add_sheet`** (mutate, с readback-подтверждением).
4. **T5.3 — адресация листа в `read_range`/`write_range`/`format_cells`.** Расширение — **необязательный закрытый аргумент листа**; доказательство каждого инструмента остаётся прежним по строгости, «лист по умолчанию» = активный (обратная совместимость). **Изменение задевает уже закоммиченные инструменты**, поэтому каждый затронутый инструмент получает **свой атомарный коммит** с прогоном своего набора тестов и нативной проверкой.
5. **T5.4 — `rename_sheet`** — только при подтверждённой безопасности (в том числе: не ломает ли переименование формулы и адресацию); иначе честный отказ с точным FAIL.

**Вне области Sprint 4:** **`delete_sheet` не реализуется** — для пилота явной необходимости нет. Микротулы форматирования и любые изменения Agent Runtime также вне области.

## 9. SPRINT 4 EXIT GATE

Sprint 4 **не заканчивается наличием отдельных API-инструментов.** После каталога обязателен end-to-end прогон.

**Сценарий (выполняется агентом по обычному запросу, без изменения Agent Runtime):**

> «Построй P&L-модель на 3 года.
> Создай отдельный лист допущений.
> Заполни исходные данные, формулы выручки/затрат/валовой прибыли/маржи,
> оформи проценты и денежные показатели, выдели заголовки
> и затем проверь расчёт.»

**Что должно быть доказано для сдачи Sprint 4:**

1. Сценарий выполняется **через Cell Tool Registry** (не скриптом вокруг него) и **без изменения** `src/agent/*`.
2. В книге действительно **два листа**; лист допущений создан инструментом, а не вручную.
3. Исходные данные и **формулы** записаны; формулы подтверждены как формулы, а расчёт — как значения после пересчёта.
4. **Оформление** (проценты, денежные показатели, выделенные заголовки) применено и подтверждено readback.
5. **Проверка расчёта** выполнена агентом (чтение результата и его сверка), а не только объявлена.
6. **Нативный прогон** на живом R7 + независимый review результата.
7. **Qwen-калибровка**: реальные вызовы через собственный путь запросов продукта, с зафиксированными наблюдаемыми максимумами (шаги / вызовы инструментов / время / байты на запрос / число ремонтов). Калибровка — **обязательная часть** выхода, как в Sprint 2/3.
8. Всё, что **не** проверено (панельный end-to-end путь, целевая сборка Astra/R7 2026.1.2.1942), записывается как **не проверено**, а не подразумевается проверенным.

## 10. Работы, выполняемые ДО начала T4

### A. Corrective task — дефект T2 в слоте `formulas` (отдельный атомарный коммит)

- **TDD → native proof → независимый review**; дефект закрывается **отдельно** и **раньше** T4.

- Область правки: только чтение формул; контракт должен честно отвечать, что именно возвращается в слоте `formulas`, в том числе в случае, когда исходник получить нельзя.

## 11. Дисциплина выполнения

- Каждый инструмент: **TDD → native verification на одноразовой книге → независимый review → атомарный коммит**; перед коммитом — свежий полный прогон (`node --test`, `static-audit`, сборка плагина, bundle-audit).
- **Никаких** push/merge/публикации; `main` не трогается.
- Ненативные прогоны (host-тесты, аудит сборки) **не доказывают** нативную совместимость — это каждый раз указывается явно.
- Ложный успех недопустим; ложная неопределённость допустима.
